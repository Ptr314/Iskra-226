# Искра 226 BASIC Simulator

[![GitHub Release](https://img.shields.io/github/release/ptr314/iskra-226.svg?style=flat)]()

Симулятор BASIC 02 микроЭВМ [«Искра 226»](https://ru.wikipedia.org/wiki/%D0%98%D1%81%D0%BA%D1%80%D0%B0_226) (разработка СССР на основе [Wang 2200](https://www.wang2200.org/)). Поддерживается экран (текстовый+графика+графопостроитель) и выполнение основной части команд Бейсика. Процессор и реальное железо НЕ эмулируется. 

## Платформы

| Система                                   | Состояние |
|-------------------------------------------|---|
| Windows XP, Vista, 7, 8, 10, 11 (32 бита) | окно и командная строка |
| Windows 7, 8, 10, 11 (64 бита)            | окно и командная строка |
| Linux с X11 (X.Org, XWayland)             | окно и командная строка |
| macOS (Intel и Apple Silicon)             | окно и командная строка |
| [Браузер (WebAssembly)](https://iskra226.emuverse.ru/)                 | страница: экран, клавиатура, диски, графопостроитель, АЦПУ |

Собранный выпуск состоит из двух файлов:

- `iskra` — окно;
- `iskra-nohead` — командная строка и диалог в терминале.

## Запуск

```
iskra ОБРАЗ                            окно, размер под экран
iskra ОБРАЗ --scale 3                  окно с целым увеличением 3
iskra --d0 A.dsk --d1 B.dsk --r1       два дисковода, второй без записи
iskra --text ЛИСТИНГ                   текстовая программа в память до запуска
iskra --printer ЛЕНТА.txt              лента АЦПУ ещё и в файл

iskra-nohead --console ОБРАЗ           диалог в терминале
iskra-nohead --list ОБРАЗ              каталог дискеты
iskra-nohead --cat ОБРАЗ ИМЯ           листинг программы
iskra-nohead --run ОБРАЗ ИМЯ [ВВОД…]   исполнить программу с образа
iskra-nohead --run-text ФАЙЛ [ВВОД…]   исполнить текстовый листинг
iskra-nohead --detok ФАЙЛ              листинг извлечённого файла
iskra-nohead --tok ФАЙЛ                трансляция текстового листинга
iskra-nohead --roundtrip ФАЙЛ          токены → текст → токены, сверка байтов
iskra-nohead --screen                  проверка экрана и знакогенератора
iskra-nohead --printer ЛЕНТА.txt …     лента АЦПУ в файл, а не на stdout
```

В браузере то же самое собрано страницей: меню «Система» и «Диски», экранная
клавиатура по рис. 2.2 руководства, а лист графопостроителя и лента АЦПУ
показываются вкладками над кадром. Пакет для выкладки на сервер собирает
`deploy/build-wasm.sh`; это статика, ни сервера приложений, ни служб.

Дисководы: `--d0` = `18F`, `--d1` = `18R`, `--d2` = `1CF`, `--d3` = `1CR`.
`--r0`…`--r3` запрещают запись на свой дисковод. Образ, названный без ключа,
идёт в нулевой. Запись идёт прямо в файл образа.

Ключ `-i` велит пропускать то, чего в симуляторе нет, вместо остановки.
Полная раскладка клавиатуры — `iskra --help`.

## Что симулируется

Машина:

- экран 80x24, коды управления дисплеем, негатив и позитив;
- знакогенератор самой «Искры»: КОИ-7 Н2, глиф 5x8 в поле 7x10;
- графический растр 560x256, наложение на знакоместа;
- лист графопостроителя отдельным окном (открывается при первом выводе в устройство);
- клавиатура: правка строки, клавиши спецфункций 0…31, `HALT`, `CONTINUE`,
  `RESET`, `STMT NUMBER`, слова Бейсика верхнего регистра;
- четыре дисковода, образы по 256256 байт;
- АЦПУ: лента своим окном, а с ключом `--printer` ещё и файлом;
- десятичная арифметика, 13 значащих разрядов.

Язык:

- числа, строки, символьные поля, массивы строк, `STR(`;
- числовые массивы до двух измерений, `DIM`, `COM`, `COM CLEAR`;
- `PRINT` с `AT(`, `TAB(`, `HEX(`, зонами и выводом на устройство,
  `PRINTUSING` с оператором образа `%`, `HEXPRINT`;
- `INPUT`, `LINPUT`, `KEYIN`;
- `FOR`/`NEXT`, `IF`/`THEN`, `GOTO`, `GOSUB`/`RETURN`, `ON … GOTO/GOSUB`,
  `STOP`, `END`, `REM`;
- `READ`/`DATA`/`RESTORE`, `CONVERT`, `PACK(`/`UNPACK(`;
- `SQR`, `ABS`, `INT`, `SGN`, `LOG`, `EXP`, `ROUND(`, `RND(`, `#PI`,
  `SIN(`, `COS(`, `TAN(`, `ARCSIN(`, `ARCCOS(`, `ARCTAN(`;
- `LEN`, `NUM`, `VAL`, `POS`, `BIN(`, `INIT`, `REPLACE`, `$TRAN(`;
- `AND`, `OR`, `XOR`, `BOOL`, `ADD`, `ADD C`, `ROTATE`;
- `MAT` — `=ZER`, `=CON`, `=IDN`, присваивание массива, `READ`, `INPUT`,
  `PRINT`, `REDIM`, `COPY`, `SEARCH`;
- `DEFFN`/`FN`, `DEFFN'`/`GOSUB'`, `RETURN CLEAR`;
- `SELECT` с таблицей устройств, единицы измерения углов;
- `ON ERROR` во всех трёх формах;
- диск: `SAVE DC`, `LOAD DC`, `LOAD DA`, `SAVE DA`, `DATA SAVE/LOAD DC`,
  `DATA SAVE/LOAD DA`, `DATA SAVE/LOAD BA`, `DATA SAVE/LOAD BT`, `DSKIP`,
  `DBACKSPACE`, `LIMITS`, `VERIFY`, `COPY`, `SCRATCH`, `SCRATCH DISK`,
  `LIST DC`, `IF END THEN`;
- графика: `¤OPEN`, `WINDOW`, `FRAME`, `NPLOT`, `DRAW`, `DDRAW`, `DOT`,
  `LABEL`, `¤COPY`, `¤MOVE`, `TURN`, `STRETCH`, `¤LET`, `PLOT`;
- диалог: приглашение `:`, правка текста программы, `RUN`, `LIST`, `CLEAR`,
  режим непосредственного счёта — и те же команды внутри программы.

Из 93 глаголов, встречающихся в корпусе, исполняются 91.

## Чего нет

Не планируется — требуется эмуляция процессора с картой памяти и
система команд БУВ:

- `ASMB`;
- `¤GIO`.

На данный момент не удалось установить порядок перевода в байт-код:

- `MAT TRN`, `MAT INV`, матричная арифметика `+`, `-`, `*`, `(K)*`;
- `TRACE`, `DATA LOAD`, `DATA SAVE` и `DATA RESAVE` без приставки,
  `LIST RES`, `MOVE END`;
- `ORIGIN`, `DNPLOT`, `NDRAW`;
- маска `hh` у `$TRAN(`, признаки `*`, `%`, `#` у `MAT SEARCH`;
- формы `LIST V`, `LIST *`, `LIST ¤`, `LIST %`, `INPUT ¤<переменная>`;
- числовая константа с отрицательным порядком.

Устройства:

- ввода, кроме клавиатуры, нет: `DATA LOAD BT` с любого устройства
  останавливает программу;
- телекоммуникационного интерфейса (`/34`, `/35`) нет;
- из управляющих кодов графического устройства `/10` пять не разобраны, и
  пакет с таким кодом отвергается целиком;
- ширина строки АЦПУ запоминается (`SELECT PRINT 0C(130)`), но переноса
  по ней нет; в окне ленты видно последние 24 строки, вся лента целиком —
  только в файле `--printer` (в браузере она видна целиком и сохраняется
  кнопкой);
- дискета, защищённая `--rN`, даёт «не пишется сектор», а не «защищена».

Прочее:

- Скорость исходной машины не симулируется. Исполнение быстрее примерно на три порядка;
- Образ дискеты подключается ключом при запуске, файлового диалога
  в окне нет (в браузере он есть, но запись там идёт только в память —
  образ приходится сохранять обратно вручную);
- строчных букв у машины нет, набранное приводится к прописным;
- знаков `` ` ``, `{`, `|`, `}`, `~` в знакогенераторе нет: по этим кодам
  стоят Ю, Ш, Э, Щ, Ч, а подчёркивание высвечивается как Ъ;
- кириллица со стандартного ввода в терминале Windows приходит не в UTF-8:
  имя файла кириллицей в диалоге набрать не получится;
- диалог в терминале повторяет экран построчно и правки клавишей `EDIT`
  не имеет;
- `^` расходится с книгой в последнем значащем разряде.

## Сборка

Выпуски собираются скриптами из [`deploy/`](deploy/README.md).

## Состав репозитория

| Каталог | Содержимое |
|---|---|
| `src/core/` | ядро: язык, экран, растр, диск, граница с хостом |
| `src/font/` | знакогенератор «Искры»: КОИ-7 Н2, глиф 5x8 в поле 7x10 |
| `src/host_common/` | общее для оконных хостов: растеризатор, образы дисков |
| `src/host_win32/` | окно на GDI, от Windows XP до 11 |
| `src/host_x11/` | окно на Xlib: X.Org и XWayland |
| `src/host_cocoa/` | окно на AppKit: NSWindow, без бандла |
| `src/host_wasm/` | канва браузера и страница вокруг неё |
| `src/host_headless/` | хост без окна: автотесты и командная строка |
| `tests/` | 35 наборов автотестов, без сторонних библиотек; проверки на корпусе идут только в отладочной сборке |
| `tools/` | питоновская модель разбора и пробы формата |
| `deploy/` | скрипты сборки выпусков |
| `docs/format.md` | журнал исследования формата: токены, таблицы переменных, грамматика операторов, открытые вопросы |
| `docs/ARTICLE-wiki*.txt` | статьи для emuverse: файловая система, оттранслированное представление, файлы данных, графический буфер |
