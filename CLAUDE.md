# CLAUDE.md

Указания для Claude Code (claude.ai/code) при работе с этим репозиторием.

## О проекте

Эмулятор Бейсика BASIC 02 микроЭВМ «Искра 226» (клон Wang 2200). Должен
одинаково исполнять оба представления программы: плоский текст в КОИ-8 и
«оттранслированный» токенизированный вид.

Стадия: **работает интерпретатор вычислительного ядра**. `STAT04`
исполняется из обоих представлений и даёт побайтово одинаковый экран.
Сделаны числа, строки, массивы, управление, `CONVERT`. Нет дисковой
подсистемы, графики и окна — только хост без окна.

Формат разобран и проверен на корпусе из 94 файлов.

## С чего начинать любую задачу

1. **`docs/format.md`** — журнал исследования формата. Это главный документ:
   токены, таблицы переменных, грамматика операторов, что доказано и чем, что
   осталось открытым. Содержит и отрицательные результаты — чтобы не повторять
   уже проделанную работу.
2. **`docs/DECISIONS.md`** — проектные решения по эмулятору с обоснованием:
   язык, отказ от Qt, выбор SDL2, раскладка каталогов, план проверки, риски.
3. **`docs/book/manual-text.txt`** — извлечённый текст руководства 1987 года.
   Там ответы на большинство вопросов по семантике операторов. Искать в нём
   прежде, чем строить гипотезы.

Если задача — «продолжай», смотреть ниже разделы **«Что дальше»**,
**«Допущения, ждущие проверки»** и **«Известные шероховатости»**: там
очередь работ, список неподтверждённых решений и мелочи, до которых руки
не дошли.

## Сборка

Подробности в `BUILD.md`. Коротко:

```
cmake -S . -B build/cmake -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
```

Компиляторы на этой машине: `C:/DEV/Qt/Tools/mingw1310_64` (GCC 13.1, для
повседневной работы) и `C:/DEV/Qt/Tools/mingw492_32` (GCC 4.9.2, цель
Windows XP). **Второй цепочкой проверять обязательно** — она и есть причина
запрета на всё новее C++11, и она ловит то, чего не заметит GCC 13.

## Технические решения (кратко; подробности в DECISIONS.md)

- **C++11**, подмножество: без исключений, без `std::regex`, без локалей.
  Тот же стиль, что в `dsk_tools`.
- **Никакого Qt.** Хост на SDL2, он же покрывает WASM через Emscripten.
  Отдельного модуля OpenGL нет — `SDL_Renderer` сам выбирает D3D/Metal/GL/WebGL.
- Цели: Windows XP…11 (MinGW 4.9.2, 32 бита), macOS, Linux, WASM.
- `libs/dsk_tools` — подмодуль, тот же, что в DISK Commander и eCat3.
  Даёт загрузчики образов и `fs_iskra226`. Qt-независим.
- Ядро (`src/core/`) не знает ни про SDL, ни про dsk_tools — только про
  `host.h`.

## Инструментарий исследования

`tools/` — питоновская модель разбора, проверенная на всём корпусе. Пути в
ней вычисляются от корня репозитория, ничего настраивать не надо.

```
py tools/hex2bin.py         # corpus/hex/*_bin.txt → build/corpus/*.bin
py tools/show.py STAT09     # листинг файла из корпуса
py tools/raw.py EDITOR 265  # сырые байты конкретной строки
py tools/verify.py          # построчная сверка всех пар «текст + токены»
```

`tools/probes/` — одноразовые скрипты, которыми получены отдельные выводы в
`docs/format.md`. Полезны как образцы, но не как библиотека.

Требуется Python 3 (в системе доступен как `py`). Сторонних пакетов не нужно,
кроме `pypdf` для извлечения текста книги.

## Устройство эмулятора

```
src/core/host.h          граница с внешним миром: экран, клавиши, секторы, время
src/core/number.*        десятичная арифметика, 13 значащих разрядов
src/core/koi8.*          перекодировка КОИ-8 в обе стороны
src/core/screen.*        БОСГИ 80x24, коды управления, позитив/негатив
src/core/ir.h            промежуточное представление
src/core/expr.*          разбор выражений — общий для обеих форм
src/core/front_tokens.*  оттранслированная форма → IR (+ таблицы переменных)
src/core/front_text.*    текстовая форма → IR (+ таблица имён)
src/core/interp.*        исполнение IR
src/font/                знакогенератор КОИ-8, вшит генератором tools/psf2c.py
src/diskio/              единственный модуль, который видит dsk_tools
src/host_headless/       хост без окна: дамп экрана, очередь клавиш
tests/                   шесть наборов, без сторонних библиотек
```

Тесты: `test_number` (арифметика), `test_screen` (экран, шрифт, хост),
`test_stat04` (обе формы дают один экран), `test_arrays`, `test_strings`,
`test_convert`, `test_deffn`. Последние содержат **вручную собранные
оттранслированные файлы**: у токенов своя кодировка, и текстовыми
примерами её не проверить.

Ключевое место — `expr.*`: обе формы сводятся к одному потоку лексем
(`Tok`), и выражение разбирает общий код. Токенизированная форма
двузначна — один байт значит разное в позиции операнда и в позиции
операции, — поэтому `TokenSource::next()` принимает `operand_expected`.
**Заглядывать вперёд можно только в том состоянии, в каком лексема потом
будет прочитана**; иначе двузначный токен разберётся не так. Проверять
конец потока надо у источника (`at_end()`), а не заглядыванием.

Что реализовано из языка: `PRINT` (`AT(`, `TAB(`, `HEX(`, зоны,
разделители), `INPUT`, присваивание в несколько целей, `DIM`/`COM` и
массивы до двух измерений, `FOR`/`NEXT`, `IF`/`THEN`, `GOTO`,
`GOSUB`/`RETURN`, `ON … GOTO/GOSUB`, `GOSUB'`/`DEFFN'`, `STOP`, `END`, `REM`,
функции `SQR`/`ABS`/`INT`/`SGN`/`LOG`/`EXP`, `#PI`.

Символьные данные: переменная — поле байт постоянной длины (16 по
умолчанию, `DIM` задаёт 1…253), массив строк — одно непрерывное поле,
`STR(` работает и слева от знака равенства, есть `LEN`, `NUM`, `VAL`, `POS`.
`BIN(` — обратное `VAL(` преобразование: `BIN(<приёмник>[,2])=<а.в.>`
записывает целую часть значения в один или два двоичных байта.

`CONVERT` в обе стороны с образами, `LINPUT`, `MAT REDIM`. Двухбайтовые
глаголы `06 <подкод> <len>` разбираются структурно все — на нереализованном
подкоде разбор останавливается точно, без рассинхронизации.

Помеченные подпрограммы: `DEFFN'` с формальными параметрами (числовыми и
символьными), `GOSUB'` с выражениями, несколько входов в одну подпрограмму,
`DEFFN'` с текстом клавиши спецфункции (разбирается, но клавиш ещё нет).
Разд. 10.4 книги и разд. «Помеченные подпрограммы» `docs/format.md`.

Нет `SELECT`, `PRINTUSING`, прочих матричных и графических операторов,
дисковых операторов, `ON ERROR`, `ASMB`.

**Три ловушки кодировки, о которые легко споткнуться снова.**

1. Первая запятая `STR(` в потоке не кодируется — после первого аргумента
   надо заглядывать в состоянии «ожидается операнд».
2. По той же причине **первый аргумент `STR(` не индексируется по
   заглядыванию**: `STR(Z¤,67)` иначе читается как `Z¤(67)`. Там работает
   только признак массива из таблиц — в `Tok` для этого отдельное поле
   `table_array`.
3. **Приёмник `BIN(` — тоже**: за ним сразу идёт значение, без разделителя,
   и `BIN(A¤)=J%` (`4B 02 22 3B`) при заглядывании читается как
   `BIN(A¤(J%))`. Оба места вызывают `parse_lvalue(target, true)`.

Во всех прочих местах индексация символьной переменной определяется по
тому, начинает ли следующий байт операнд (разд. 7).

**Размеры массивов в оттранслированной форме есть только в таблицах
переменных**: оператор `DIM` там несёт одни индексы. Читает их
`build_vars()` в `front_tokens.cpp` по разд. 6 `docs/format.md`. Осторожно с
`MAT REDIM`: выросший массив получает новый индекс, и в `DIM` стоят
«теневые» индексы с размерами уже после переопределения.

**«Строка-скаляр или массив строк» решается только по адресам**: у скаляра
поле «число элементов» числом элементов не является вовсе (у `A¤` в `EDITOR`
там 129 при длине 1). `build_vars()` идёт по лестнице правил из разд. 6
`docs/format.md`: чётный размерный код, вторая размерность, затем точные
равенства с разностью адресов соседних записей таблицы 1. Когда адресов нет
(невыполнявшиеся файлы, `STAT05`), остаётся догадка по числу элементов, и она
ошибается в сторону «массив».

Полезно для оценки охвата:

```
iskra --run-file build/corpus/STAT04.bin 30 .05   запуск извлечённого файла
iskra --run-text corpus/hex/STAT04_text.txt 30 .05
```

Прогнать разбор по всему корпусу и увидеть, на чём он встаёт:

```
for f in corpus/bin/* build/corpus/*.bin; do
    ./build/cmake/iskra.exe --run-file "$f" 1 1 1 2>&1 | grep '^разбор:'
done | sed 's/строка [0-9]*: //' | sort | uniq -c | sort -rn
```

На сегодня целиком разбирается **1 из 94** оттранслированных файлов и
**1 из 28** текстовых листингов. Цифра низкая потому, что программе нужны
*все* её глаголы сразу, а корпус — в основном дисковые утилиты и редакторы.
После помеченных подпрограмм остаток встаёт почти целиком на дисковых
глаголах: `54` (`SELECT`) — 18 файлов, `2D` (`LOAD`) — 14, `DC` в позиции
операнда — 8, `34` (`ON ERROR`) — 8, `75`/`81`/`64` — по 6–7.

## Что дальше

По убыванию отдачи:

1. **Дисковая подсистема** — `SELECT`, `DATA LOAD/SAVE DC`, `SCRATCH`,
   каталог «Искры» поверх `Host::disk_read/write`. Даст самый большой
   скачок охвата и потребует решить, как эмулятор видит дискету: секторы
   в `host.h` уже есть, файловой системы поверх них нет. Разд. 18 книги.
2. **`ON ERROR`** (глагол `34`, 8 файлов) и коды ошибок — нужен список кодов
   из книги.
3. **`PRINTUSING` и оператор `%`** — образы печати. `format_by_image()`
   в `interp.cpp` уже умеет ровно этот синтаксис, его надо переиспользовать.
4. Остальные матричные операторы: `MAT` (`=ZER`/`CON`/`IDN`), `MAT COPY`,
   `MAT SEARCH`, `MAT SORT`.
5. **Хост на SDL2** — окно, клавиатура, знакогенератор в текстуру. Ядро к
   этому готово: оно знает только `host.h`. Заодно оживит клавиши
   специальных функций: `DEFFN'` их уже разбирает, нажимать нечем.
6. Графика (`DOT`, `DRAW`, `NPLOT`, `LABEL`, `STRETCH`) и `ASMB` — отдельные
   проекты, см. `docs/DECISIONS.md` разд. 1.

## Допущения, ждущие проверки

Всё это работает, но подтверждения в книге не имеет. Если появится живая
машина или её ПЗУ — проверять в первую очередь.

- **Прокрутка** экрана при печати ниже 24-й строки.
- **Пороги экспоненциальной записи**: принято «плотно при порядке от −12
  до 12».
- **Мантисса E-формата — восемь знаков после точки.** Основание — один
  пример в разд. 13.6.
- **Условие цикла проверяется в `NEXT`**, а не при входе в `FOR`.
- **`TAB(` двигает курсор только вправо**; что делает при позиции левее
  текущей — неизвестно.
- **`CONVERT` без образа** прижимает число вправо к длине приёмника.
  Книга такой формы не описывает вовсе.
- **`NUM`**: пробел между знаком и цифрами допускается, хвост из одних
  пробелов входит в длину. Сходится со всеми тремя примерами книги, но
  выведено из них, а не прочитано.
- Поле символьной переменной **растёт по требованию**, если обращение
  выходит за описанные размеры: по таблицам «строка-скаляр или массив
  строк» не различаются.
- **Фактические параметры `GOSUB'` вычисляются все до первого
  присваивания.** Формальный параметр — обычная глобальная переменная, и
  корпус зовёт подпрограммы через их же параметры (`EDITOR` 6855:
  `GOSUB '100(L3,A%,1)` при `DEFFN '100(L1,L4,L3)`), но там порядок ничего
  не меняет — различающего примера нет ни в книге, ни в корпусе.
- **При повторе имени подпрограммы побеждает первое `DEFFN'`.** Книга
  говорит только, что машина ищет просмотром текста программы.

## Известные шероховатости

- Кириллица в аргументах командной строки не доходит до программы
  (`--cat ОБРАЗ СТЬЮД` не находит файл). Расходятся кодировки `argv` и
  каталога; с латинскими именами всё работает.
- `NUM`, `LEN`, `VAL`, `POS` в текстовой записи требуют скобок, в
  токенизированной их нет вовсе — разбор терпит оба варианта.

## Что уже известно про машину

- Экран: **80 позиций x 24 строки**, атрибуты только позитив и негатив.
- `AT(строка, позиция [, сколько_стереть])` — отсчёт с единицы; третий
  аргумент стирает вправо от курсора, курсор остаётся на месте.
- Коды управления БОСГИ: `01` НЗ, `03` КТ, `07` ЗВ, `08` ВШ, `09` ГТ,
  `0A` ПС, `0C` ПФ, `0D` ВК, `11` СУ1, `12` СУ2. Код для **НС**
  («в первую позицию следующей строки») в таблице книги не найден.
- В позиции `24` машина высвечивает **¤**, а не доллар. Знакогенератор в
  `src/font/font.cpp` подменяет этот глиф.

## Диски

Образы дискет лежат вне репозитория:
`DSKCommander/docs/samples/Iskra226/345_dk_spb/`.

**Автоопределению типа диска верить нельзя:** 8-дюймовые образы «Искры» не
отличаются по геометрии от CP/M GMD-7012, и `detect_fdd_type()` выбирает
CP/M — каталог читается как мусор. Поэтому `DiskImage::open()` берёт из
автоопределения только формат файла (`format_only = true`), а тип диска и
файловую систему навязывает всегда. Других дисков у эмулятора не бывает.

## Корпус

- `corpus/hex/` — 79 hex-дампов: `*_bin.txt` токенизированные, `*_text.txt`
  текстовые листинги. 12 пар «одна программа в обоих видах».
- `corpus/bin/` — 43 двоичных файла без текстовых пар.

**Осторожно с парами:** у `M1`, `STAT00`, `STAT05`, `STAT001`, `STAT01`
текстовая и двоичная копии — разные редакции программы. Для сверки годятся
`EDITOR`, `VICT`, `STAT02`, `STAT03`, `STAT04`, `STAT08`, `STAT09`.

## Правила работы

- Гипотезы о формате проверять на всём корпусе, а не на одном файле. В
  `docs/format.md` есть примеры того, как правдоподобная догадка разваливалась
  на втором файле.
- Найденное — записывать в `docs/format.md` с указанием, чем доказано
  (файл, строка, байты). Отрицательные результаты тоже.
- `docs/ARTICLE-wiki.txt` — статья для emuverse; таблицы токенов там должны
  быть отсортированы по возрастанию токена.
- Скан книги (`docs/book/*.pdf`) в git не попадает — он в `.gitignore`.
