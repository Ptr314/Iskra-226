# CLAUDE.md

Указания для Claude Code (claude.ai/code) при работе с этим репозиторием.

## О проекте

Эмулятор Бейсика BASIC 02 микроЭВМ «Искра 226» (клон Wang 2200). Должен
одинаково исполнять оба представления программы: плоский текст в КОИ-8 и
«оттранслированный» токенизированный вид.

Стадия: проектирование. Формат уже разобран и проверен на корпусе из 94
файлов.

## С чего начинать любую задачу

1. **`docs/format.md`** — журнал исследования формата. Это главный документ:
   токены, таблицы переменных, грамматика операторов, что доказано и чем, что
   осталось открытым. Содержит и отрицательные результаты — чтобы не повторять
   уже проделанную работу.
2. **`docs/DECISIONS.md`** — проектные решения по эмулятору с обоснованием:
   язык, отказ от Qt, выбор SDL2, раскладка каталогов, план проверки, риски.
3. **`docs/book/manual-text.txt`** — извлечённый текст руководства 1987 года.
   Там ответы на большинство вопросов по семантике операторов. Искать в нём
   прежде, чем строить гипотезы.

## Технические решения (кратко; подробности в DECISIONS.md)

- **C++11**, подмножество: без исключений, без `std::regex`, без локалей.
  Тот же стиль, что в `dsk_tools`.
- **Никакого Qt.** Хост на SDL2, он же покрывает WASM через Emscripten.
  Отдельного модуля OpenGL нет — `SDL_Renderer` сам выбирает D3D/Metal/GL/WebGL.
- Цели: Windows XP…11 (MinGW 4.9.2, 32 бита), macOS, Linux, WASM.
- `libs/dsk_tools` — подмодуль, тот же, что в DISK Commander и eCat3.
  Даёт загрузчики образов и `fs_iskra226`. Qt-независим.
- Ядро (`src/core/`) не знает ни про SDL, ни про dsk_tools — только про
  `host.h`.

## Инструментарий исследования

`tools/` — питоновская модель разбора, проверенная на всём корпусе. Пути в
ней вычисляются от корня репозитория, ничего настраивать не надо.

```
py tools/hex2bin.py         # corpus/hex/*_bin.txt → build/corpus/*.bin
py tools/show.py STAT09     # листинг файла из корпуса
py tools/raw.py EDITOR 265  # сырые байты конкретной строки
py tools/verify.py          # построчная сверка всех пар «текст + токены»
```

`tools/probes/` — одноразовые скрипты, которыми получены отдельные выводы в
`docs/format.md`. Полезны как образцы, но не как библиотека.

Требуется Python 3 (в системе доступен как `py`). Сторонних пакетов не нужно,
кроме `pypdf` для извлечения текста книги.

## Корпус

- `corpus/hex/` — 79 hex-дампов: `*_bin.txt` токенизированные, `*_text.txt`
  текстовые листинги. 12 пар «одна программа в обоих видах».
- `corpus/bin/` — 43 двоичных файла без текстовых пар.

**Осторожно с парами:** у `M1`, `STAT00`, `STAT05`, `STAT001`, `STAT01`
текстовая и двоичная копии — разные редакции программы. Для сверки годятся
`EDITOR`, `VICT`, `STAT02`, `STAT03`, `STAT04`, `STAT08`, `STAT09`.

## Правила работы

- Гипотезы о формате проверять на всём корпусе, а не на одном файле. В
  `docs/format.md` есть примеры того, как правдоподобная догадка разваливалась
  на втором файле.
- Найденное — записывать в `docs/format.md` с указанием, чем доказано
  (файл, строка, байты). Отрицательные результаты тоже.
- `docs/ARTICLE-wiki.txt` — статья для emuverse; таблицы токенов там должны
  быть отсортированы по возрастанию токена.
- Скан книги (`docs/book/*.pdf`) в git не попадает — он в `.gitignore`.

## Родственные репозитории

- DISK Commander — там живёт детокенизатор `viewer_basic_iskra226.cpp`,
  построенный на знаниях из `docs/format.md`. При изменении понимания формата
  проверять, не нужно ли поправить и его.
- eCat3 — эмулятор ретрокомпьютеров; оттуда берутся `ini.h` и `lodepng`,
  а также образцы сборки под WASM.
