# Сборка

Нужны CMake 3.16+, Ninja и компилятор C++11. **Сторонних библиотек нет
вовсе** — только стандартная. Единственное, что нужно сверх неё, — заголовки
самой системы для окна: под Windows они идут с цепочкой, под Linux это
`libx11-dev` (Debian, Ubuntu) либо `libX11-devel` (Fedora, openSUSE).

```
git clone https://github.com/Ptr314/Iskra-226.git
cd Iskra-226
cmake -S . -B build/cmake -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
```

## Выпуски

Готовые архивы собираются скриптами из `deploy/` — сборка, `ctest` и
упаковка одним заходом:

```
deploy/build-win-i386.bat     Windows XP…11, 32 бита, MinGW 4.9.2
deploy/build-win-mingw.bat    Windows 7…11, 64 бита, MinGW 13.1
deploy/build-win-msvc.bat     Windows 10…11, 64 бита, MSVC
deploy/build-linux.sh         Linux с X11
```

Получается `deploy/release/iskra-<версия>-<система>-<разрядность>[-<компилятор>].zip`.
Версия берётся из файла `VERSION`, пути к цепочкам — из `deploy/vars-*.cmd`.
Подробности — `deploy/README.md`.

## Параметры

Собирается два исполняемых файла:

- `iskra-nohead` — без окна: командная строка и диалог в терминале;
- `iskra` — окно. Под Windows и под Linux; на прочих системах CMake скажет
  об этом и соберёт первый.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `ISKRA_HOST_WINDOW` | `ON` | хост с окном средствами самой системы |
| `ISKRA_BUILD_TESTS` | `ON` | автотесты |
| `ISKRA_CORPUS_TESTS` | по типу сборки | наборы, работающие на корпусе |

Окно делается без сторонних библиотек: под Windows это `user32` и `gdi32`,
под Linux — голый Xlib, дальше будут AppKit и канва браузера. Почему не
SDL2 — `docs/DECISIONS.md`, разд. 14.

**Наборов тридцать пять, выпускная сборка прогоняет тридцать четыре.**
Корпус в git не входит, и на машине, где его нет, проверки на нём падали бы
на отсутствующих файлах, а не на коде. Поэтому `ISKRA_CORPUS_TESTS` при
`CMAKE_BUILD_TYPE=Debug` включён, а при всяком другом выключен; значение не
запоминается в кэше, так что сменить состав можно сменой типа сборки. Задать
руками — `-DISKRA_CORPUS_TESTS=ON`:

```
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
```

Ключ задаёт определение `ISKRA_CORPUS_DIR`, и прячутся под него **отдельные
случаи, а не наборы целиком**: `test_arrays`, `test_program`,
`test_tokenize` и `test_detokenize` собираются всегда и без корпуса просто
проверяют меньше — двадцать случаев из двадцати шести. Целиком выпадает
один `test_stat04`: он весь стоит на корпусе, и проходить впустую ему
незачем. Прочие тридцать наборов корпуса не касаются вовсе.

## Linux

```
sudo apt install cmake ninja-build g++ libx11-dev      # Debian, Ubuntu
sudo dnf install cmake ninja-build gcc-c++ libX11-devel   # Fedora
```

Дальше обычным заходом, как выше. CMake скажет `хост с окном: X11`; если
скажет `нет`, значит не найден Xlib — ставится пакет с заголовками.

Окно идёт на голом Xlib: ни toolkit'а, ни XRender, ни разделяемой памяти.
На Wayland работает через XWayland — своего хоста ему пока нет. Нужен экран
TrueColor в 32 бита на точку; такие сейчас все, но если попадётся иной,
эмулятор скажет об этом и не станет показывать мусор.

Статически на Linux не увязывается: `libX11` статической библиотекой не
поставляется почти нигде. У `iskra` остаются `libX11`, `libstdc++` и
`libc`, у `iskra-nohead` — две последние.

## Windows XP

Целевая цепочка — MinGW 4.9.2, 32 бита (в поставке Qt это
`Tools/mingw492_32`). Именно ради неё в ядре запрещены средства новее C++11.

```
export PATH="/c/DEV/Qt/Tools/mingw492_32/bin:$PATH"
cmake -S . -B build/cmake-xp -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake-xp
```

Линковка статическая (`-static`), поэтому получаются два самостоятельных
файла без сопровождающих DLL: `iskra-nohead.exe` тянет только `kernel32`, `shell32`
и `msvcrt`, `iskra.exe` — их же плюс `user32` и `gdi32`. Всё это есть на
любой Windows от XP до 11.

**`-static` навешен только на `iskra-nohead` и `iskra`** — тесты остаются на динамическом
рантайме и тянут `libgcc_s_dw2-1.dll` с `libstdc++-6.dll`. Поэтому `ctest`
этой сборки надо запускать с той же цепочкой на `PATH`, что и сборку. Без
неё 32-битные тесты подхватывают 64-битные DLL и падают все разом с
`Exit code 0xc000007b` — это не поломка кода, а перепутанная разрядность
рантайма.

Проверять сборку этой цепочкой стоит регулярно: GCC 4.9.2 ловит то, чего
не заметит GCC 13. Так, например, обнаружилась кириллическая буква в имени
переменной — GCC 13 её проглотил.

## Знакогенератор

`src/font/font_data.cpp` порождается из `src/font/koi7-5x8.txt` —
знакогенератора самой «Искры», глиф 5x8 в поле 7x10. Файл лежит в
репозитории готовым, при обычной сборке генератор не запускается. После
правки шрифта:

```
py tools/font2c.py
```

Сам `koi7-5x8.txt` снят со скана рис. 3.1 руководства по БОСГИ и тоже лежит
готовым; пересобрать и сверить его можно пробой (нужен Pillow):

```
py tools/probes/bosgi_font.py --check
```

## Проверка руками

```
iskra ОБРАЗ            окно: диалог с машиной, как за настоящей
iskra ОБРАЗ --scale 3  то же покрупнее (без ключа — под размер экрана)
iskra --d0 A.dsk --d1 B.dsk --r1     два дисковода, второй без записи

iskra-nohead --console ОБРАЗ      то же в терминале, без окна
iskra-nohead --screen             экран, коды управления, знакогенератор
iskra-nohead --chart 16           таблица кодов растром
iskra-nohead --list ОБРАЗ         каталог дискеты
iskra-nohead --cat ОБРАЗ STAT04   листинг программы с дискеты
iskra-nohead --detok ФАЙЛ         листинг ранее извлечённого файла

iskra-nohead -i ОБРАЗ ...         пропускать ASMB и $GIO вместо остановки

iskra-nohead --run ОБРАЗ STAT04 30 .05        запуск программы с дискеты
iskra-nohead --run-file ФАЙЛ 30 .05           то же из ранее извлечённого файла
iskra-nohead --run-text corpus/hex/STAT04_text.txt 30 .05   то же из листинга
```

Корпус в репозиторий не входит; примеры выше подразумевают его на прежнем
месте, в `corpus/`.

Аргументы после имени программы подаются на клавиатуру строками ввода —
прогон получается воспроизводимым, и обе формы одной программы можно
сравнить простым `diff`.

## Дисководы

Образы подключаются ключами `--d0`…`--d3` — по дисководу на ключ. Номера те
же, что адреса в операторе `SELECT`:

| ключ | адрес |
|---|---|
| `--d0` | `18F` |
| `--d1` | `18R` |
| `--d2` | `1CF` |
| `--d3` | `1CR` |

Образ, названный без ключа, идёт в нулевой дисковод. Ключи `--r0`…`--r3`
запрещают запись на свой дисковод — это заклеенная прорезь дискеты.

**Запись идёт прямо в файл образа**, сектор за сектором, не дожидаясь выхода:
`SAVE DC` в окне или в `--console` меняет файл на диске. Команды `--list`,
`--cat` и `--run` образ только читают: они и задуманы как воспроизводимый
прогон.
